Registry / How to choose / Code review

Start with one project · Claude Code

Review your next diff with a reusable checklist

Install one skill, check where it landed, then ask Claude Code to review your uncommitted changes. You keep control of which findings become edits.

1. Choose the skill

Sentry's code-review covers runtime errors, security, performance, design and test coverage. Its examples focus on Python/Django and TypeScript/React. It is a useful starting point for those stacks; adapt its Sentry-specific conventions to your project's rules.

Read the complete skill · Upstream repository

2. Install into your project

Requires Node.js 22.20+ and Claude Code. Open a terminal in the Git project you want to review, then run:

npx --yes skills@1.7.0 add getsentry/skills --skill code-review --agent claude-code --copy --yes

This installs only code-review into .claude/skills/code-review/ in the current project. With --copy, files go directly to that directory; .agents/skills/code-review/ appears in the installer's summary but is not created by this command. The command does not use the global installation flag.

If this project already has .claude/skills/code-review/, inspect it before running the command: this installation can replace it.

3. Check the installation

npx --yes skills@1.7.0 list --agent claude-code

The project list should include code-review. Open .claude/skills/code-review/SKILL.md and confirm its name is code-review and its heading is Sentry Code Review.

4. Try it on a small change

Start a new Claude Code session in that project. With uncommitted changes available, send:

Use the code-review skill to review my uncommitted changes.
Follow this repository's instructions.
Check git status --short --untracked-files=all.
Read both staged and unstaged diffs and the contents of untracked files.
Report concrete bugs and missing tests with file locations and reasons.
Do not edit files. If no actionable issues are found, say so.

Check whether each finding cites the actual diff and explains a reproducible problem. Installing a skill does not establish that its review is correct.

Remove it from this project

npx --yes skills@1.7.0 remove code-review --agent claude-code --yes

Remove any skill-installer lockfile changes from your Git diff only if you no longer want them tracked with the project.

Installation checked on 2026-09-30 with skills 1.7.0 on macOS in an empty Git project. The skill file was compared with upstream commit d18b7aa. This checks delivery, not model review quality. The command follows the upstream repository's current branch; later content can change.
