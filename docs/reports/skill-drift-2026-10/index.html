When skill guides change after a registry scan

The registry’s checks flagged 1,386 of 5,750 skill guides (24.1%) as no longer matching the version it scanned.

Among the files compared, 78 added new commands to run, 106 added new external URLs, and 45 widened tool permissions. These signals can overlap. Substantive edits also include changed code examples and larger instruction rewrites.

These are changes to review, not safety verdicts. A new URL may be a citation, and a command may be an example. The results do not establish author intent.

How we measured

We selected guides that the registry’s install-pin checks had marked as changed or unavailable. For each changed guide, we verified the archived file against its recorded SHA-256 digest before comparing it. We resolved each upstream branch once and used that commit for file retrieval, move searches and evidence links. When the recorded path was missing, we searched the same commit tree for a guide with the archived directory name or frontmatter name. We then applied textual rules to distinguish commands, URLs, permission additions, code examples and instruction edits. The observations span 2026-10-21 through 2026-10-21 (UTC). These are observations at different times, rather than one simultaneous snapshot of every source.

Input checks: 2026-10-17 through 2026-10-20. Content history starts 2026-10-17; this is not the date an author edited a file. Archive snapshot at b2456cc40342.

Precise comparison rules
  • Priority is: adds new commands to run, adds new external URLs, widens tool permissions, changes code examples, rewrites instructions, then small edits. Flags can overlap; primary labels cannot.
  • A new command is a download using curl or wget piped to sh, bash or Python; an npx, uvx or pip install command; Python, bash, sh, Node, Ruby or Perl followed by a script path; or a relative executable beginning with ./. Interpreter script suffixes are .py, .sh, .js, .mjs, .rb and .pl; relative executables also accept .cjs, .ps1 or no suffix. Commands are compared as whitespace-normalized sets, joining shell backslash-newline continuations. A changed command counts as new even inside an example.
  • A closed, nonempty fenced block in one of these languages is a code example: bash, c, console, cpp, go, javascript, js, perl, php, powershell, ps1, py, python, python3, ruby, rust, sh, shell, sql, terminal, ts, typescript, zsh. A block is changed when its whitespace-normalized content is new. Plain text, JSON and YAML fences do not qualify by themselves.
  • New external URLs are new HTTP or HTTPS URLs, including new paths on an existing domain. Localhost and loopback addresses are excluded. New hostnames are recorded separately.
  • Frontmatter fields named allowed-tools, allowed_tools, tools, tool, permissions or permission are checked at any mapping depth. Added flattened tokens count as wider permissions; list order is ignored, values split on whitespace or commas, mapping paths are kept, and false or null grants no tokens. This does not model tool-specific permission semantics. Unparseable YAML is flagged.
  • Instruction rewrites exceed six added plus removed nonempty body lines after removing whitespace and Markdown formatting characters (` * _ # > | ~ -). Letter case and other punctuation remain significant. Paragraph reflow with identical joined normalized text counts as zero; other frontmatter changes do not count toward this threshold. Remaining edits, including identical bytes, are small edits.
  • A moved guide must be a SKILL.md in the same resolved commit with a matching parent directory or archived frontmatter name. Directory matches take precedence, then the lexicographically first matching path. Its content is compared normally. No match after a complete search means removed; failed or truncated trees and incomplete name searches remain unchecked.
  • Unavailable sources are checked independently: a missing repository is unavailable or inaccessible; an accessible repository with a missing recorded branch has a branch failure. Unknown branches and other errors remain unresolved.
  • Only SKILL.md is compared; bundled assets are outside this report. No commands are run. Successful responses and missing-file responses are cached. Transient errors are retried twice and not cached; rate-limit responses are reported without repeated retries. Reusing the cache preserves previously resolved commits.

What this means for you

Users: Prefer installs pinned to a commit and digest. For a registry guide offering verified installation, use npx skills add <registry guide URL> and check its recorded commit and digest. Re-read SKILL.md and review bundled files before updating. A pin identifies the checked bytes; it is not a guarantee of safety.

Authors: Tag releases, keep skill paths stable, and describe changes so users can make informed update decisions.

Registries and installers: Pin content by commit and digest, and show content history so users can see what changed after a scan.

Limits

122 missing-path searches could not be completed; 11 content comparisons and 0 moved-file comparisons failed; 50 availability checks remain unresolved. Every affected row retains its reason in the data. Unchecked paths are neither confirmed moves nor confirmed removals.

Textual heuristics can miss unfenced code, prose permissions and non-HTTP links. Formatting normalization can hide meaningful small edits. Cached errors and missing responses reflect the observation, not guaranteed current availability.
