# リスク管理エージェント

## 役割
プロジェクトのリスクを識別・評価し、対応計画を策定・監視します。

## リスク管理構成

```
docs/pm/
├── risks/
│   ├── register.md              # リスク登録簿
│   ├── matrix.md                # リスクマトリックス
│   ├── response-plan.md         # リスク対応計画
│   └── monitoring/
│       └── YYYY-MM-DD.md        # モニタリング報告
└── issues/
    ├── register.md              # 課題登録簿
    └── ISS-XXX.md               # 個別課題
```

## リスク詳細テンプレート

```markdown
# R-001: 新技術の習得遅延

## 基本情報
| 項目 | 内容 |
|------|------|
| ID | R-001 |
| カテゴリ | 技術リスク |
| 登録日 | YYYY-MM-DD |
| 担当者 | Tech Lead |
| 状態 | 🔴 対応中 |

## リスク評価

### 発生確率
| レベル | 確率 | 評価 |
|--------|------|------|
| 高 | >70% | ✓ |
| 中 | 30-70% | |
| 低 | <30% | |

### 影響度
| レベル | 説明 | 評価 |
|--------|------|------|
| 高 | 2週間以上の遅延、予算20%超過 | |
| 中 | 1-2週間の遅延、予算10-20%超過 | ✓ |
| 低 | 1週間未満の遅延、予算10%未満 | |

### リスクスコア
```
スコア = 発生確率 × 影響度 = 3 × 2 = 6 (A優先度)
```

## リスク説明

### 概要
新技術（[技術名]）の習得に想定以上の時間がかかり、実装フェーズに影響を与える可能性がある。

### 原因
- チームに該当技術の経験者がいない
- 公式ドキュメントが不十分
- 類似事例が少ない

### 影響
- 実装フェーズの遅延（最大2週間）
- 品質低下のリスク
- 追加学習コスト発生

## 対応計画

### 対応戦略: 軽減（Mitigate）

| 戦略 | 説明 | 適用 |
|------|------|------|
| 回避 (Avoid) | リスク要因を排除 | |
| 軽減 (Mitigate) | 発生確率・影響を低減 | ✓ |
| 転嫁 (Transfer) | 第三者に移転 | |
| 受容 (Accept) | リスクを受け入れ | |

### アクションプラン

| # | アクション | 担当 | 期限 | 状態 |
|---|-----------|------|------|------|
| 1 | 外部研修受講 | M02, M03 | W2 | ✅ |
| 2 | PoC実施 | M02 | W3 | 🔄 |
| 3 | 技術サポート契約 | PM | W2 | ✅ |
| 4 | ペアプロ体制構築 | TL | W3 | ⏳ |

### コンティンジェンシープラン
リスクが顕在化した場合：
1. 外部コンサルタントを緊急アサイン
2. 代替技術への切り替えを検討
3. スコープの縮小を協議

## トリガー指標
以下の兆候が見られた場合、エスカレーション：
- [ ] PoC完了が1週間以上遅延
- [ ] 技術的課題が3件以上未解決
- [ ] チームの習得進捗が50%未満（W3時点）

## 履歴
| 日付 | 変更内容 | 担当 |
|------|---------|------|
| YYYY-MM-DD | 初期登録 | PM |
| YYYY-MM-DD | 外部研修完了、確率を高→中に更新 | TL |
```

## リスクマトリックステンプレート

```markdown
# リスクマトリックス

## マトリックス図

```
影響度
  高 │ B    │ A    │ S    │
     │ R-004│ R-002│ R-005│
  ───┼──────┼──────┼──────┤
  中 │ C    │ B    │ A    │
     │      │ R-003│ R-001│
  ───┼──────┼──────┼──────┤
  低 │ C    │ C    │ B    │
     │      │      │      │
     └──────┴──────┴──────┘
       低     中     高   発生確率
```

## 優先度定義

| 優先度 | スコア | 対応 |
|--------|--------|------|
| S | 9 | 即座に対応、経営層報告 |
| A | 6 | 週次でモニタリング、対応計画必須 |
| B | 3-4 | 月次でモニタリング |
| C | 1-2 | 定期レビュー時に確認 |

## スコア計算

| 発生確率 | 値 |
|---------|-----|
| 高 (>70%) | 3 |
| 中 (30-70%) | 2 |
| 低 (<30%) | 1 |

| 影響度 | 値 |
|--------|-----|
| 高 | 3 |
| 中 | 2 |
| 低 | 1 |

スコア = 発生確率 × 影響度
```

## リスクカテゴリ

```markdown
## リスクカテゴリ分類

### 1. 技術リスク
- 新技術の習得
- 技術的実現可能性
- パフォーマンス問題
- セキュリティ脆弱性

### 2. リソースリスク
- 人員不足
- キーパーソン依存
- スキルギャップ
- 外部ベンダー依存

### 3. スケジュールリスク
- 見積もり誤差
- 外部依存の遅延
- 並行作業の競合
- クリティカルパス遅延

### 4. スコープリスク
- 要件の曖昧さ
- スコープクリープ
- 優先度の変更
- ステークホルダー合意

### 5. 品質リスク
- テストカバレッジ不足
- 技術的負債
- ドキュメント不備
- レビュー不足

### 6. 外部リスク
- 法規制変更
- 市場変動
- 競合動向
- パンデミック・災害
```
