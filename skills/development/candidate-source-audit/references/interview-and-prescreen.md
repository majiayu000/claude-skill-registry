# 面试准备 + 评分表 + 非正式预筛

候选人通过源码尽调、决定推进后用本文件。三部分:① 面试题怎么设计 ② 一页纸评分表 ③ 微信/电话非正式预筛。

---

## 一、面试题设计原则

1. **每道题针对候选人真实做过的东西**(用尽调挖到的代码细节命名,如"你那个项目的并发为什么设上界 N")。开口就让对方知道"我们真读过你的代码",最容易问出真假。
2. **每道关键题标注 ✅好答案 / 🚩危险信号**,让面试官当场可判。
3. **按目的分组**,而非按知识点:
   - A. 验证他真懂自己的代码(尤其重度 AI 代写者:哪些他设计、哪些 Codex 写、举一个否决 AI 方案自己重写的例子)
   - B. 攻盲区 / 岗位核心(没做过的那一半,用白板题现场验**迁移能力**,如"从 0 设计带依赖的多 Agent 任务调度器")
   - C. 验 AI-Native 是真思考还是模式匹配
   - D. 软性:带人意愿、不确定中推进、投入度/抗枯燥
4. **追到设计权衡层**("为什么这样而不那样"),别停在"能跑"——代笔者会卡在复述 happy path。
5. **学生/低年级生**:别用"资深工程师"标尺,看系统思维的原生质量 + 迁移能力 + 能否在不确定里从 0 定义系统。

### 因人定制:验"相反的东西"
- 有代码、有手艺但缺某块经验的人 → 验"脑子能不能拉伸到没做过的地方"(白板题)。
- 思维对口但代码不可验证的人 → **先要代码**,验"手(代码)是不是真的、是工程还是研究脚本"。

## 三、微信/电话非正式预筛话术

老板授权"先简单聊一下"时用。**这不是正式面试。**

> **定位:你是"热情的前门",老板是"严格的关卡"。** 对已通过尽调的抢手候选人,这一场
> **70% 是吸引 + 建立好感 + 摸兴趣/档期,30% 才是轻度验真。** 目标不是考倒他,是让他**想来**,
> 并带回 4 个判断:①真不真强/真不真 AI-Native ②有没有兴趣来 ③档期/投入度 ④推不推进正式面。

### 开场白(点名其具体作品 = 立刻证明"我们是懂技术的团队")
> Hi <名字>,我是 <你>,和 <老板> 一起在做 <方向> 的东西。翻了下你的 GitHub——<某具体项目/某具体设计>挺有意思,正好跟我们在搞的事很对路。想简单聊聊,看有没有机会一起做点东西。最近方便的话**语音聊 15 分钟**?

能约**语音**就约——文字摸不出真实水平和热情。

### 节奏(5 步)
1. 暖场 + 夸到点子上(从其作品切入)
2. 让他讲自己的东西(开放式,听他自然展开)
3. 抛岗位"钩子"(讲成他会兴奋的样子:不写 CRUD / 从 0 设计系统 / 能带人)
4. 轻轻探三件事:代码掌控、对岗位核心方向的兴趣、能投入多少
5. 收尾:给下一步(约老板正式聊)+ 问档期

### 话术库(口语,一次一个,顺着接)
- "你 <某项目> 最得意的一个设计是哪块?或踩过最深的坑?" → 真 builder 会两眼放光往深里讲。
- "你平时怎么跟 AI/Codex 配合写代码?哪些你自己定、哪些丢给它?" → 自然问出代码掌控度,不像考试。
- "你研究过 <harness/相关项目> 的实现?最吸引你的是哪块?" → 验真研究还是收藏。
- "有没有想过做 <岗位核心,如多 Agent 协作>?感觉怎么搞?" → 兴趣探测 + 顺手剧透岗位 + 活体测盲区。
- "你大X对吧,课多吗?实习能投多少时间?远程还是来现场?什么时候能开始?" → 实在事,老板一定会问。

### 别做的事
- ❌ 连珠炮技术题 / 甩白板题(那是正式面的活,微信甩=把人聊死)
- ❌ 端着 JD"别浪费时间"的筛人腔(他已过筛子,现在是吸引模式,要暖)
- ❌ 暴露尽调深度到瘆人(夸"看了你 X 项目"=好;"我逐行读了你某文件的某逻辑"=瘆人)
- ❌ 把盲区说成"你的短板"(要包成"我们正好在做这个,你有兴趣一起搞吗")

### 收尾 + 回报模板
- 聊得来:"挺投缘,我跟 <老板> 同步下,约个时间你俩正式聊聊?他想看技术细节,你最近哪天方便?"
- 给上级回报:`技术:__(真懂/一般);AI-Native:__;对核心方向的兴趣与悟性:__;投入度:年级__、能投__、__可开始、远程/现场;来电程度:__。建议:☐推进正式面 ☐再看 ☐pass。一句话:__。`

> 赢的标准不是"问出多少",而是"他聊完更想来了 + 你带回了那 4 个判断"。
