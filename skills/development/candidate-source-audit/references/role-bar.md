# 岗位标尺(模板,按岗位替换)

> 本文件定义"你这个岗位的尺子"。本 skill 的反指标/适配判断都以这里为准。
> **用法:把下面的示例改成你自己岗位的硬门槛、反指标、本质。** 下面装的是一个
> 通用的 "AI Agent Harness 工程岗" 示例,仅作模板参考。

## 模板结构(逐项填写)
- **岗位本质**:一句话说清你真正要的人在做什么。
- **可验证要求**:必须能提供 GitHub / 可验证项目?(决定本 skill 的源码验证力度)
- **硬门槛**:学历/语言/系统经验等不可妥协项。
- **反指标**:看到就扣分、明确"不等于能力"的东西。
- **明确不适合的人**:一票否决画像。

---

## 示例:AI Agent Harness 工程岗

### 岗位本质
构建 AI Agent 的运行环境(Harness),让模型参与软件生产。
**一句话:模型是 Agent,代码是 Harness——给模型构建一个可以工作的世界。**
要做的是工具系统 / 任务调度与依赖 / 上下文与记忆 / 多 Agent 协作,而不是接 API 做应用。

### 可验证要求
要求提供 GitHub 或可验证项目;没有可验证内容则难以评估 —— 所以源码验证是刚需。

### 硬门槛(示例)
- 至少从 0 到 1 做过一个完整系统(**上线过**)
- 能**独立做系统设计**(不是只写接口)
- 熟悉 Python / Node / Go 至少一门
- 必须具备其一:做过复杂系统(调度 / 工具 / 状态管理) **或** 工程工具(CLI / 插件 / 自动化)
- 能带人,或至少具备"可以带人"的意愿;能在不确定环境下推进落地

### 反指标(示例,≠ 系统能力)
RAG / 向量库 / 知识库 · Dify / LangFlow / Flowise / Coze / n8n 低代码 · prompt 编排 ·
纯调 API · 纯 CRUD · 框架依赖不懂底层 · 纯模型微调 / ML 调包作业 · 把 AI 当应用/赚钱工具。

### 明确不适合的人(示例)
只做 CRUD · 只会调 API / 写 prompt · 依赖框架不理解底层 · 没做过完整系统 · 不愿参与招聘或带人。

---

## 评估时如何用这把尺
- 候选人代码命中越多**反指标** → 越不适配。
- 找**硬门槛**的代码级证据:上线过的完整系统?独立系统设计?调度/工具/状态/CLI/自动化?
- 区分"AI 使用者/应用者/研究者"与"AI-Native 系统构建者"。
- 即使技术达标,也要看**潜力与投入度**(年级×专业,见 rubric 第 5 节)与**带人意愿**。
