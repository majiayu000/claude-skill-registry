## 2. 套壳玩具 vs 真系统的 tells

### 🚩 套壳的铁证(看到就警惕)
- **声明却从不使用的字段**:如某任务类声明了 `depends_on`(依赖)字段却全代码从未引用 → "调度/依赖"是摆设,实际只是 `for` 顺序循环。**这类"架构词汇齐全但无实质"是最高频的伪装。**
- **N 个"专业 Agent" = 同一个执行函数换不同 system prompt**:函数被复用,每个 "agent" 只是人设不同 → 是 prompt 编排,不是多智能体。
- **"低代码智能体" = 一行 `<script>` CDN**:低代码平台挂个悬浮窗当"AI 功能"。
- **假 RAG**:号称检索增强,实为 if-else 写死答案。
- **假"爬虫/采集"**:把粘贴的文本用正则切分(并无真正抓取)。
- **体积出卖一切**:号称复杂系统/平台的仓库却只有几十 KB。
- **AI 一键生成**:署名异常(作者写成某 AI 工具)、分支名带工具名、一天内突击 commit、全是 "Add files via upload" 网页拖传 → 代码漂亮但未必他懂(要验掌控度,见面试)。

### ✅ 真 builder 的正面信号
- **手写底层、不套框架**:自写多 Provider LLM 抽象层而非现成框架;敢下沉。
- **工程化的健壮性**:有界并发、批量失败自动降级为单条重试、部分失败继续。
- **真·状态/记忆/工具系统**:如"聚合行为 → LLM 生成记忆草案 → 用户 accept/edit/reject"这类人在环记忆闭环。
- **给模型造环境**:自己写模拟器/沙盒/工具系统,让 Agent 在里面 Plan→Observation→Action —— 这就是 harness 思维本身。
- **真迭代史**:有版本演进、commit 有节奏,而非一次性 dump。
- **研读 harness 内部**:fork 并研读 agent 框架的开源实现、自写 agent skill。

### 核实代码归属(git)
```bash
git shortlog -sne                              # 各作者提交数排行
git log --pretty='%an %ad %s' --date=short     # 谁、何时、提交了什么
git log --author="名字" --oneline | wc -l       # 本人到底写了多少
git blame <核心文件>                            # 关键逻辑逐行谁写的
```
**经典塌方**:旗舰/论文代码挂在**合作者**账号下,候选人本人 0 commit、0 行 → "一作"是论文署名,工程实绩为零。

## 3. 岗位反指标清单(示例,按岗替换)

命中越多越不适配。下例是一个"AI Agent Harness 岗"会**明确贬低**的(≠ 系统能力):
- RAG / 向量库 / 知识库问答
- Dify / LangFlow / Flowise / Coze / n8n 等低代码 / 工作流编排
- prompt 编排
- 纯调大模型 API
- 纯 CRUD / 业务增删改查
- 依赖框架但不懂底层
- 纯模型微调(LoRA 等)/ ML 调包作业(教科书级公开数据集练习)
- "用 AI 接单赚钱"这类 AI 应用 / AI 使用(≠ AI 系统构建)

## 4. AI-Native 思维:真 vs 假

- **真 AI-Native**:把模型视为在"他构建的环境(工具/记忆/调度/约束)"里被编排干活的 worker;关注怎么给模型一个能持续工作的世界。代表动作:写工具系统、写记忆机制、造模拟器/沙盒、研读 harness 内部、code-as-action(让 Agent 写代码而非调 JSON 工具)。
- **假 / 浅**:把 AI 当成"调一下拿结果"的 API、当成微调对象、当成赚钱工具;架构词汇会背但代码无实质。
- **研究范式 ≠ harness 范式**:能发 benchmark/消融论文,但那是把模型当研究对象,不等于会造运行环境。研究味重的人要单独验"落地 vs 发论文"的取向。

## 5. 年级 × 专业 → 潜力与"能否用心 commit"

种子岗要"能长期投入、能自己定义系统、留得住"。光看能力不够,加这层:

- **Runway**:剩余在校时间够不够支撑实习→转化?(临近毕业/已毕业=投入度风险)
- **方向自洽**:专业 / 研究方向 / 项目选择是否**都指向该岗位**?自洽=内在驱动证据;样样沾=广度探索期、未定型。
- **竞争性拉力 / 分心源**:读研、自己创业(已是别处"CTO")、主业无关、出国路线、抢手被挖。
- **内在动机 vs 工具性动机**:自发造东西/啃 harness(内在) vs 拿 hackathon/实习/论文镀金(工具性)。
- **专业能预测产出形态**:偏业务/信息管理类专业 → 业务+低代码;与 AI 无关的主修 → AI 多为课外 side project;自定的对口 AI 方向 → 自洽。非顶校生竞争性拉力小、最可能珍惜,但能力天花板要单独看。

> **反直觉规律(提示决策者)**:能力越强/越抢手的,留存风险越高;留存意愿最高的,往往能力最错位。
> 甜区 = 方向自洽 + runway 足 + 内在动机 + 不临近毕业。

## 6. "不可验证 ≠ 造假"(纠偏,务必执行)

搜不到候选人的代码时,**别默认成"注水"**。严格区分两种,从外部看一模一样、性质天差地别:

- 「私有 / 未完成」:学术研究默认私有直到论文发表;私有仓库对任何搜索都隐形;在读学生进行中的项目本就常私有。**候选人主动写"还没达标/还在调"反而是诚实信号**(注水的人不会承认没做出效果)。
- 「夸大 / 不存在」:本该公开、无保密理由的东西(如标准课程作业)却全无踪影,且简历主链接还是死链 → 更可能是注水/课程练习。

**关键区分动作**:
- 看项目**性质**:前沿在研(合理私有) vs 标准学生作业(没理由私有)。
- 看**逻辑**:absence of evidence ≠ evidence of absence。
- **唯一可靠的破局**:让候选人把私有仓库 share / 屏幕共享走一遍代码。给得出且配得上简历 → 不扣分;给不出 / 远配不上 → 才是问题。

## 7. 复核 AI 自己的结论(用户的严谨)

AI 放大尽调效率,但**最终判断尺度与纠偏由人来把**。下结论前自检:
- 把"搜不到""没做完"草率判成"造假"了吗?(见第 6 节)
- 用"反指标"误伤了人吗?看的是**最高水位**(代表作)还是被平均水位拖累?
- 对一个候选人,有没有给到和对简历同一套**证伪**标准——也包括证伪自己的初判?

向上汇报时,呈现的是**人的判断框架**,AI 是执行尽调的工具。
