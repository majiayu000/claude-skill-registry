# Daily

Быстрый локальный скилл: человек спрашивает — сразу получает ответ в чате.

## Граница

Работай только с текущим отделом. Не обходи штаб, соседние отделы, календарь и внешние системы. GitHub разрешён только тогда, когда `tasks/README.md` называет GitHub Issues активным источником задач этого отдела.

## Алгоритм

1. Определи сегодняшнюю дату, ISO-неделю и все семь дат недели из системного времени. Имя плана всегда вычисляется заново: `reports/WNN-plan.html` или формат, принятый текущим отделом.
2. Прочитай `AGENTS.md`, `README.md` и блок "Активный режим" в `tasks/README.md`.
3. Собери активные задачи из одного указанного источника:
   - режим `локальные файлы` → прочитай `tasks/*.md`, кроме `README.md` и `_template.md`;
   - режим `GitHub Issues` → через GitHub CLI прочитай открытые Issues репозитория из блока "Активный режим", включая их body и URL; отдельно проверь, что среди локальных файлов не осталось задач со статусом `новая`, `в работе`, `на приёмке` или `заблокирована`.
4. Если активный режим не указан, источник недоступен или в GitHub-режиме осталась хотя бы одна активная локальная задача, сразу покажи конфликт источников и не угадывай.
5. Не показывай задачи со статусом `завершена` или `снята`.
6. Остальные задачи распредели ровно в один раздел по приоритету:
   - `просрочено или заблокировано`, если дата прошла или статус `заблокирована`;
   - `в работе`, если статус `в работе`;
   - `запланировано сегодня`, если дата совпадает с сегодняшней.
7. Не дублируй одну задачу в нескольких разделах.
8. Не угадывай состояние по свободному тексту. Если обязательное поле отсутствует, пометь это как пробел записи.
9. Если living plan уже существует, обнови его после сборки фактов:
   - сохрани все семь дней; прошедшие дни показывают закрытый факт и выполненные задачи, текущий день выделен, будущие дни остаются планом;
   - замени только содержимое пар `daily:updated` и `daily:kanban`; сохрани скрытую пару `daily:day-slice` для совместимости;
   - каждая карточка имеет ровно один `data-area`, который задаёт цвет карточки;
   - Area Explorer строится из карточек канбана и не хранит дубль задач;
   - не меняй цели Areas, список часовых поясов, ключ localStorage и состояние чекбоксов Wealth.
10. Если плана нет, сообщи это одной строкой после дневного среза и предложи запустить `planning`. Не создавай недельный план из daily.
11. Сразу ответь в чат. Не проводи интервью и не меняй задачи или Issues без подтверждённого факта.

## Формат ответа

```markdown
## Сегодня · ГГГГ-ММ-ДД

### В работе
- <задача> — <следующий шаг> · <ссылка на файл или Issue>

### Запланировано сегодня
- <задача> — <результат> · <ссылка на файл или Issue>

### Просрочено или заблокировано
- <задача> — <дата или блокер> · <ссылка на файл или Issue>
```

Пустые разделы не показывай. Если активных задач нет, ответь: "На сегодня активных задач отдела не найдено".

## Запрещено

- создавать отдельный дневной список;
- менять статусы без факта;
- скрывать просроченные и заблокированные задачи;
- превращать ответ в планирование недели;
- задавать вопросы до первого ответа.
- удалять прошедшие дни или сокращать доску до "сегодня + два дня";
- переписывать HTML целиком и сбрасывать локальное состояние Wealth.
