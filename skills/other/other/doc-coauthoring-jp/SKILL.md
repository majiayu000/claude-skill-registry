# 日本語文書 共同編集・推敲スキル

## 概要

日本語文書の共同執筆・編集を支援するスキルです。推敲チェックリスト、敬語レベル調整、文章構成パターンの適用、レビューワークフローの管理を包括的にサポートします。

## 日本語推敲チェックリスト

文書を推敲する際は、以下の項目を順番に確認してください。

### 1. 表記チェック

| チェック項目 | 確認内容 | 例 |
|---|---|---|
| **誤字脱字** | 変換ミス、タイプミスがないか | ✕ 以外 → ○ 意外（予想外の意味の場合） |
| **送り仮名** | 文化庁「送り仮名の付け方」に準拠しているか | ✕ 行なう → ○ 行う |
| **同音異義語** | 文脈に合った漢字を使用しているか | 対象/対称/対照、意志/意思 |
| **漢字・ひらがなの使い分け** | 公用文ルールに従っているか | ○ ください（補助動詞はひらがな） |
| **数字表記** | 統一されているか（全角/半角、漢数字/アラビア数字） | ○ 3つ（横書き）/ ○ 三つ（縦書き） |
| **句読点** | 「、」「。」で統一されているか | ✕ 「，」「．」の混在 |

### 2. 敬語レベル一貫性チェック

- 文書全体で敬語レベルが統一されているか確認する
- 「です・ます調」と「だ・である調」が混在していないか
- 尊敬語・謙譲語・丁寧語の使い分けが正確か
- 二重敬語になっていないか（✕「お読みになられる」→ ○「お読みになる」）

### 3. 文体統一チェック

| 項目 | です・ます調 | だ・である調 |
|---|---|---|
| **用途** | ビジネス文書、マニュアル、社外向け | レポート、論文、社内技術文書 |
| **語尾** | 〜です、〜ます、〜でしょう | 〜だ、〜である、〜であろう |
| **接続** | しかしながら、そのため | しかし、したがって |
| **印象** | 丁寧、柔らかい | 客観的、断定的 |

### 4. 論理構成チェック

- 主語と述語の対応関係は正しいか
- 接続詞の使い方は適切か
- 段落の区切りは論理的か
- 冗長な表現はないか

## 文章構成パターン

### 起承転結

日本の伝統的な文章構成法です。エッセイ・スピーチ・コラムに適しています。

```
起（導入）: テーマの提示、読者の関心を引く
承（展開）: テーマの深掘り、具体例の提示
転（転換）: 新たな視点、意外性のある展開
結（結論）: まとめ、読者への呼びかけ
```

**使用場面**: コラム、スピーチ原稿、ブログ記事、挨拶文

### PREP法

明快な説明・プレゼンテーションに適した構成法です。

```
Point（結論）  : 最初に主張・結論を述べる
Reason（理由） : なぜそう言えるのか根拠を示す
Example（具体例）: 具体的な事例・データで裏付ける
Point（結論）  : 改めて結論を繰り返す
```

**使用場面**: プレゼン資料、提案書、報告書、メール

### 結論ファースト（ピラミッド原則）

ビジネスシーンで最も推奨される構成法です。

```
結論     : 最も伝えたいことを冒頭に
根拠1    : 結論を支える理由・データ
  └ 補足情報
根拠2    : 結論を支える理由・データ
  └ 補足情報
アクション : 次に何をすべきか
```

**使用場面**: 経営報告、意思決定文書、稟議書、上司への報告

## 敬語調整機能

文書の敬語レベルを変換する際のガイドです。

### レベル定義

| レベル | 名称 | 語尾例 | 使用場面 |
|---|---|---|---|
| **Lv.1** | カジュアル | 〜だよ、〜だね、〜しよう | 社内チャット、親しい同僚 |
| **Lv.2** | 標準丁寧 | 〜です、〜ます、〜ですね | 社内メール、通常の会議 |
| **Lv.3** | ビジネス | 〜でございます、〜いたします | 社外メール、取引先との会議 |
| **Lv.4** | フォーマル | 〜賜りたく存じます、〜申し上げます | 式典挨拶、公式文書、謝罪文 |

### 変換例

**カジュアル（Lv.1）**:
> 来週の会議、13時からに変更になったよ。資料は金曜までに共有するね。

**標準丁寧（Lv.2）**:
> 来週の会議ですが、13時からに変更になりました。資料は金曜日までに共有します。

**ビジネス（Lv.3）**:
> 来週の会議につきまして、開始時刻が13時に変更となりました。資料は金曜日までにお送りいたします。

**フォーマル（Lv.4）**:
> 来週のお打ち合わせにつきまして、開始時刻を13時に変更させていただきたく存じます。資料は金曜日までにお届け申し上げます。

## 根回しプロセスの文書化

重要な提案・意思決定の前に行う根回しを文書化するガイドです。

### 根回しチェックリスト

1. **関係者の特定**: 意思決定に関わるステークホルダーを洗い出す
2. **事前説明資料の作成**: 要点をまとめた1枚サマリーを用意する
3. **個別説明の記録**: 誰に・いつ・何を説明し、どんな反応だったか記録する
4. **懸念事項の整理**: 各関係者から出た懸念と対応策を整理する
5. **合意形成の確認**: 全関係者の賛否状況を一覧化する

### 根回し記録テンプレート

```markdown
## 根回し記録: 【案件名】

| 日付 | 相手 | 役職 | 説明内容 | 反応・意見 | 対応策 | 状況 |
|---|---|---|---|---|---|---|
| YYYY/MM/DD | 【氏名】 | 【役職】 | 【要旨】 | 【反応】 | 【対応】 | 賛成/保留/反対 |
```

## 共同編集ワークフロー

### フロー全体像

```
1. 起草 → 2. セルフレビュー → 3. レビュー依頼 → 4. フィードバック
   → 5. 修正 → 6. 再レビュー → 7. 承認 → 8. 最終確定
```

### 各ステップの詳細

| ステップ | 担当 | アクション | 成果物 |
|---|---|---|---|
| **起草** | 執筆者 | 構成パターンを選択し、初稿を作成 | 初稿ドキュメント |
| **セルフレビュー** | 執筆者 | 推敲チェックリストで自己確認 | セルフチェック済み原稿 |
| **レビュー依頼** | 執筆者 | レビュー観点を明記して依頼 | レビュー依頼メッセージ |
| **フィードバック** | レビュアー | コメント・修正提案を記載 | フィードバックコメント |
| **修正** | 執筆者 | フィードバックを反映 | 修正版ドキュメント |
| **再レビュー** | レビュアー | 修正内容を確認 | 承認 or 追加フィードバック |
| **承認** | レビュアー | 最終承認 | 承認記録 |
| **最終確定** | 執筆者 | 版番号を付与し確定 | 確定版ドキュメント |

### レビュー依頼テンプレート

```markdown
## レビュー依頼

- **文書名**: 【タイトル】
- **執筆者**: 【氏名】
- **依頼日**: YYYY/MM/DD
- **希望回答期限**: YYYY/MM/DD
- **レビュー観点**:
  - [ ] 内容の正確性
  - [ ] 論理構成
  - [ ] 敬語・文体の適切さ
  - [ ] 誤字脱字
  - [ ] その他: 【自由記述】
- **補足**: 【背景や注意点】
```

### 修正履歴の記録

```markdown
## 修正履歴

| 版 | 日付 | 修正者 | 修正内容 | レビュアー |
|---|---|---|---|---|
| v1.0 | YYYY/MM/DD | 【氏名】 | 初稿作成 | — |
| v1.1 | YYYY/MM/DD | 【氏名】 | 【修正概要】 | 【氏名】 |
| v2.0 | YYYY/MM/DD | 【氏名】 | 承認・確定版 | 【氏名】 |
```

## 生成時の確認事項

文書の推敲・共同編集を開始する前に、以下を確認してください：

1. **文書の種類**: 何のための文書か（報告書、提案書、メール等）
2. **読者**: 誰が読む文書か（社内/社外、役職レベル）
3. **敬語レベル**: Lv.1〜Lv.4 のどのレベルか
4. **文体**: です・ます調 / だ・である調
5. **構成パターン**: 起承転結 / PREP / 結論ファースト / 指定なし
6. **レビュー範囲**: 全体推敲 / 部分修正 / 敬語調整のみ
