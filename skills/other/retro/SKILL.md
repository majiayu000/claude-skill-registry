# Retro

Ретро смотрит назад. Сначала полностью закрой разбор недели, только затем разрешай переход к `planning`.

## Граница

Работай со всеми задачами текущего отдела. Не обходи другие отделы и не собирай общий срез Personal Corp.

Записи задач и системы результатов остаются источниками истины. HTML — датированное представление недели.

## Этап 1. Собрать факты

1. Определи календарную неделю и её даты.
2. Прочитай `AGENTS.md`, `README.md` и блок "Активный режим" в `tasks/README.md`.
3. Собери задачи из источников, действовавших в пределах недели:
   - режим `локальные файлы` → прочитай `tasks/*.md`, кроме `README.md` и `_template.md`;
   - режим `GitHub Issues` → через GitHub CLI прочитай Issues указанного репозитория, созданные, обновлённые, закрытые или остававшиеся открытыми в пределах недели;
   - если дата перехода в GitHub попадает внутрь недели → дополнительно прочитай локальные записи со статусом `завершена` или `снята` до даты перехода включительно.
4. Если после даты перехода остался хотя бы один локальный файл со статусом `новая`, `в работе`, `на приёмке` или `заблокирована`, остановись и покажи конфликт источников.
5. Включи:
   - задачи, созданные, запланированные, изменённые или завершённые в пределах недели;
   - открытые задачи, перенесённые с прошлой недели;
   - завершённые задачи со ссылкой на результат и приёмкой;
   - снятые задачи с датой и причиной; они считаются закрытыми, а не незавершёнными;
   - незавершённые и заблокированные задачи.
6. Для ссылки на результат проверь только доступность указанного пути или URL. Не выдумывай содержание недоступного результата.
7. Покажи полный недельный срез до выводов.

Если записей задач и Issues нет, остановись: фактов для ретро недостаточно. Не реконструируй неделю из памяти чата.

## Этап 2. Разрешить незавершённое

Для каждой незавершённой задачи требуется одно явное решение:

- продолжить с конкретным следующим шагом;
- уменьшить масштаб и переписать результат;
- оставить заблокированной с конкретным блокером;
- снять как больше не нужную: поставить статус `снята`, записать дату решения в поле `Завершена` и причину в `Итог`.

Не переноси задачу автоматически только потому, что неделя закончилась.

Каждое решение запиши в действующий источник задачи: локальный файл или GitHub Issue, согласно "Активному режиму". Снятую GitHub Issue после обновления body закрой, чтобы planning не считал её открытым обязательством.

## Этап 3. Интервью

После показа фактов задавай по одному вопросу:

1. Что повторно помогало завершать работу?
2. Что повторно мешало или создавало лишнюю работу?
3. Какое одно изменение постоянных правил подтверждается несколькими случаями?
4. Что материально изменилось в Области отдела?
5. Какую цель этой Области предложить для следующей недели?

Не спрашивай о факте, который уже есть в задаче или по ссылке на результат.

Если повторения нет, не меняй `AGENTS.md`. Запиши наблюдение только в отчёт.

Перед изменением правила покажи точную формулировку и получи явное решение founder.

## Этап 4. Сохранить отчёт

Создай самодостаточный HTML:

```text
reports/ГГГГ-WNN-retro.html
```

Отчёт содержит:

- период и название отдела;
- полный срез задач;
- ссылки на записи задач и результаты;
- решения по незавершённым задачам;
- повторяющиеся успехи и блокеры;
- принятое изменение правила или отметку, что изменения нет;
- место для ссылки на план следующей недели.
- секцию `Area Interview` с фактом, подтверждённым системным улучшением и предложенной целью Области на следующую неделю.

Используй семантический HTML и встроенный CSS без сборщика. Отчёт должен читаться на широком и узком экране. Не загружай внешние данные во время открытия.

В шапке напиши:

> Исторический срез недели. Текущее состояние хранится в записях задач.

## Этап 5. Проверка и приёмка

Проверь:

- число задач в отчёте совпадает с недельным срезом;
- у каждой завершённой задачи есть ссылка на результат и приёмка;
- ссылки открываются или честно помечены недоступными;
- факты отделены от выводов;
- HTML не содержит секретов;
- изменение правил подтверждено решением founder;
- HTML содержит закрытые `html`, `head`, `body`, `main` и `section`, а число открывающих и закрывающих структурных тегов совпадает;
- каждая относительная ссылка из отчёта разрешается в существующий локальный файл;

Открой отчёт человеку. Ретро завершено только после приёмки отчёта и фиксации решений в задачах.

## Запрещено

- начинать `planning` до завершённого ретро;
- выполнять задачи во время ретро;
- скрывать незавершённые задачи;
- обновлять постоянное правило по одному случаю;
- исправлять состояние только в HTML;
- копировать в отчёт приватное содержимое результата вместо ссылки.
